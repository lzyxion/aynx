# 코드 관례

이 파일에는 **두 번 이상 깨진 규칙**만 적는다. 한 번 실수한 것은 그 날짜의 `log/` 항목에
남기고, 같은 실수가 다른 파일에서 되풀이되면 그때 여기로 올라온다.

## 메뉴를 닫는 코드는 **값을 스냅샷한 뒤에** 온다

팝오버·컨텍스트 메뉴처럼 "열려 있는 동안에만 존재하는 상태"(`menu`, `tileMenu`, `ctxTab` …)
에서 **파생된 값**(`$derived`, `{@const}`)은 닫는 순간 사라진다. 항목 핸들러가 닫기부터
부르고 그 아래에서 파생값을 읽으면 Svelte 가 그 값을 다시 계산하며 `null` 을 가리켜
`Cannot read properties of null` 로 죽는다.

**이런 예외는 화면에 아무 흔적도 남기지 않는다** — 메뉴가 닫히는 것까지는 성공하므로
"눌리긴 눌렸다" 로 보이고 기능만 조용히 없다. 콘솔을 열지 않으면 발견되지 않는다.

규칙: 메뉴 항목은 **통로 함수 하나**를 거친다. 그 함수가 `스냅샷 → 닫기 → 실행` 순서를
혼자 책임지고, 대상은 **콜백의 인자**로 넘어온다. 마크업 쪽 핸들러가 메뉴 상태를 직접
읽을 일이 없으면 순서를 뒤집을 자리도 없다.

그 순서의 **구현은 하나뿐이다** — `src/lib/browser/menu-runner.ts` 의 `runOnMenu`
(2026-09-05 리팩토링 ②). 네 곳이 같은 세 줄을 각자 베껴 적고 있었고, 항목이 늘 때마다 그
세 줄을 다시 적는 자리가 곧 순서가 뒤집히는 자리였다.

```ts
export function runOnMenu<T>(
  target: () => T | null | undefined, // 함수로 받는다 — 스냅샷 시점이 이 파일 안이다
  close: () => void,
  fn: (target: T) => void | Promise<void>,
): void {
  const snapshot = target();                                   // 1. 스냅샷
  close();                                                     // 2. 닫기
  if (snapshot !== null && snapshot !== undefined) void fn(snapshot); // 3. 실행
}
```

```svelte
onclick={() => runOnMenu(() => menu?.entry, closeMenu, revealEntry)}  <!-- ✅ -->
onclick={() => { closeMenu(); revealEntry(entry); }}  <!-- ❌ 닫은 뒤에 파생값을 읽는다 -->
```

대상이 없는 항목(붙여넣기·새로고침처럼 "지금 폴더" 가 대상인 것)은 `runAfterClose(close, fn)`
— 닫는 순서만 지킨다. 상위가 모달을 여는 항목에서 백드롭이 남아 있으면 그 클릭을 가로챈다.

지금 있는 통로들 (전부 위 두 함수 위에 얹혀 있다):

| 파일 | 함수 | 넘기는 것 |
| --- | --- | --- |
| `src/lib/browser/FileMenu.svelte` | `onEntry(fn)` | `SftpEntry` |
| `src/lib/browser/HostMenu.svelte` | `onHost(fn)` | `HostEntry` |
| `src/lib/PaneHost.svelte` | `runTileMenu(fn)` | `HostBox` (탭 + 패널) |
| `src/lib/Tabs.svelte` | `runTabMenu(fn)` | 탭 id |
| `src/lib/Tabs.svelte` (워크스페이스 목록) | `runOnMenu(() => id, closeWsMenu, openWorkspace)` · 새 워크스페이스는 `runAfterClose` | 워크스페이스 id |
| `src/lib/StatusBar.svelte` (하단 독 워크스페이스 칸 우클릭) | `onWorkspaceMenu(fn)` | 워크스페이스 id |

메뉴 항목을 추가했으면 **콘솔을 한 번 열고 눌러 본다**. 이 버그는 그 한 번으로만 잡힌다.

지금까지의 게이트는 `npm run check`(0 errors / 0 warnings)와 `npm run build` 둘이었다.
**`npm test`(vitest) 를 그 줄에 더한다** — 순수 모듈(`src/lib/*.ts`)의 회귀 테스트가 저장소에

npm run check && npm run build && npm test

## Tauri 명령은 **기본 `async fn`** 이다 — 동기는 예외고, 예외에는 근거 주석이 붙는다

동기 `#[tauri::command]` 는 **웹뷰 UI 스레드에서 인라인으로 돈다** (Tauri v2 는 IPC 를
커스텀 프로토콜 핸들러에서 받고, `tauri-macros` 가 동기 명령을 `ExecutionContext::Blocking`
으로 만든다. `async fn` 이면 tokio 런타임으로 나간다).

그런데 **살아 있는 세션의 출력이 웹뷰로 가는 길이 전부 그 스레드를 지난다** —
`Channel::send` → `webview.eval`, 1KB 이상인 덩어리는 한 번 더
`plugin:__TAURI_CHANNEL__|fetch` 왕복(이것도 동기 명령이다). 그 길에서 전송이 **한 번이라도**
실패하면 그 세션의 출력은 **영구히 죽는다**: 채널 번호는 보내기 전에 올라가고 JS 쪽
`Channel` 은 빠진 번호를 영원히 기다린다. 프로세스는 살아 있고 입력도 들어가는데 화면만
검은 타일이 남는다.

즉 **UI 스레드를 오래 잡는 동기 명령 하나가 관계없는 다른 터미널을 침묵시킨다.** 명령을
고친 사람과 증상을 보는 사람이 다른 자리라 스스로는 절대 발견되지 않는다.

규칙:

- 디스크·네트워크·프로세스 실행·프로세스 종료·파이프를 만지는 명령은 **무조건**
  `async fn` + `tauri::async_runtime::spawn_blocking`. "이 파일은 작다" · "이 명령은 드물다"
  는 근거가 되지 않는다 — 디스크가 바쁘면 수 KB 쓰기도 수십 ms 다.
- **애매하면 `async`.** 비용은 스레드 홉 하나뿐이고, 잘못 고른 대가는 침묵하는 터미널이다.
- 동기로 남길 수 있는 것은 **마이크로초 단위 메모리 작업뿐**이고, 그때는 `#[tauri::command]`
  바로 위에 **왜 동기여도 되는지 근거 주석**을 적는다. 근거가 없는 동기 명령은 리뷰에서
  되돌린다.
- 동기라야 **더** 옳은 경우도 있다 — `pause_*_output` / `resume_*_output` 처럼 **호출
  순서가 곧 정확성**인 짝(뒤집히면 수문이 닫힌 채 남아 세션이 영원히 침묵한다). `async` 는
  두 호출을 각각 런타임 태스크로 만들어 순서 보장을 없앤다. 이런 것도 근거를 적는다.
- `tauri::State` 는 수명에 묶여 `spawn_blocking` 안으로 옮길 수 없다. 필요한 `Arc` 만
  복제해 옮기거나(`pty::Sessions` 가 `Arc<Mutex<…>>` 인 이유), 소유권을 통째로 옮긴다
  (`close_session` 이 표에서 `remove` 한 `Session` 을 그대로 넘기는 방식).
- 느린 일을 **잠금 위에서 하지 않는다.** 표에서는 `Arc` 만 꺼내 나오고 잠금은 곧바로 푼다
  (`pty::writer_of` · `ssh::attach_parts`). 그러지 않으면 블로킹 풀로 밀어내도 그 잠금을
  기다리는 다른 명령이 결국 UI 스레드에서 멈춘다.
- **로컬 PTY 생성은 `SPAWN_LOCK` 으로 직렬화한다** (ConPTY 동시 생성 경쟁 — 자식이 파이프
  핸들을 교차 상속해 출력 파이프가 죽는다. 생성만 세우고 비용은 블로킹 풀에서만 든다.
  [2026-09-05-conpty-spawn-race.md](log/2026-09-05-conpty-spawn-race.md)).

동기 → `async` 로 바꿀 때는 **백엔드 안의 호출부를 반드시 다시 훑는다.** 프런트는 `invoke`
라 시그니처 변화가 없지만, Rust 쪽 직접 호출은 `let _ = 명령(...)` 한 줄이 퓨처를 버리며
**컴파일도 경고도 통과한 채 조용히 죽는다** (`reap.rs` 에서 실제로 났다 — 세션 누수 그물이
통째로 무력해졌다).

## 아이콘만 바꾸면 exe 에 반영되지 않는다 — `build.rs` 를 touch 한다

`src-tauri/icons/*` 는 **tauri-build 가 빌드 스크립트 단계에서** exe 리소스로 박는다. 그런데 cargo
는 `build.rs` 의 재실행 여부를 소스·`rerun-if-changed` 기준으로 정하므로 **아이콘 파일만 바뀐
경우 `cargo build` 도 `tauri dev` 도 리소스를 다시 넣지 않는다** — 창·작업표시줄 아이콘이 옛것
그대로다. 두 번 겪었다 (2026-09-07 아이콘 적용, 같은 날 사용자 교체본).

```
touch src-tauri/build.rs && (cd src-tauri && cargo build)
```

확인은 리소스 추출로 한다 — `[System.Drawing.Icon]::ExtractAssociatedIcon(exe)` 를 PNG 로 저장해
`icons/32x32.png` 와 픽셀 비교. 앱은 **다시 띄워야** 하고, 작업표시줄에 **고정한** 바로가기는
Windows 아이콘 캐시 때문에 고정 해제·재고정(또는 `ie4uinit.exe -show`)이 필요할 수 있다.

## 화면 문구는 `t()` 를 거친다

새로 쓰는 **사용자에게 보이는 문구**는 `.svelte` 안의 한국어 리터럴이 아니라 사전에 넣고
`t("<네임스페이스>.<키>")` 로 부른다 (docs/log/2026-09-17-i18n.md).

```svelte
import { t } from "$lib/i18n/i18n.svelte.js";
{t("settings.actions.save")}                       <!-- ✅ -->
{t("settings.row.note", { label })}                <!-- ✅ 이어 붙이지 말고 자리표시자 -->
저장                                                <!-- ❌ 이미 옮긴 영역에서는 리뷰에서 되돌린다 -->
```

- **한국어가 기준이다.** `i18n/ko/<ns>.ts` 에 먼저 적고, **같은 커밋에서** `i18n/en/<ns>.ts`
  에 같은 키를 적는다. 빼면 `npm run check` 가 그 자리에서 멈춘다 (영어 사전이
  `Record<keyof typeof ko…, string>` 이다).
- **주석·문서·로그는 한국어 그대로다.** 번역 대상은 화면에 보이는 글자뿐이다.
- **문자열에 HTML 을 넣지 않는다.** `<strong>` 이 끼던 문장은 마크업에 맞춰 키를 쪼갠다.
- **이어 붙여 만들던 문장은 자리표시자 하나로 합친다** — 영어는 어순이 다르다.
  없는 인자는 `{이름}` 글자 그대로 남으니 빠뜨리면 화면에서 보인다.
- `{{이름}}`(스니펫 자리표시자)처럼 **다른 코드가 읽는 표식**은 두 언어 모두에서 그대로 둔다.
- 후보 표(`TAB_STYLES`·`APP_MODES` …)의 값은 문장이 아니라 **문구 키**다. 표의 키는
  `settings.toml` 에 저장되므로 그대로 두고 라벨만 바꾼다 (아래 "id 는 안 바뀐다" 규칙).

**옮기지 않은 화면은 이제 없다** (2026-09-17, 단계 ①~⑤ 완료). 규칙은 하나다 —
**`src/**` 의 사용자에게 보이는 문구는 전부 `t()` 를 지나고, Rust 가 만드는 것은 `tr!` 을
지난다.** 한국어 리터럴이 남아 있으면 리뷰에서 되돌린다. 예외는 넷뿐이고 각자 이유가 코드에
적혀 있다: **드리프트 표**(`automation-presets.ts` ↔ `automation_presets.rs`) · **사용자 파일에
적히는 값**(`EXAMPLE_TRIGGERS` · `settings.toml`/`sessions.toml` 머리 주석) ·
**`LANGUAGE_NAMES`**(언어 이름은 어느 언어로 보든 제 글자로 적는다) ·
**주석·`console.*`·`eprintln!`·테스트 단언**.

**프런트가 분기하는 실패에는 문구 비교 대신 이유 코드를 쓴다.** 백엔드 오류 문구의 한국어
조각을 `includes()` 로 맞춰 보고 화면을 가르던 자리가 넷 있었는데, 그 글자를 옮기면 분기가
**조용히** 죽는다(화면에 흔적이 남지 않는다). 그래서 문구는 번역하고, 갈래는 언어를 타지 않는
**ASCII 접두사** 하나로 가른다 — `[exists]` · `[not-empty]` · `[session-gone]` · `[cancelled]`.
표는 `src-tauri/src/errors.rs` 와 `src/lib/error-reason.ts` 에 같은 글자로 있고, **화면에 찍기
전 `stripReason` 으로 뗀다**(사용자는 대괄호를 볼 일이 없다). 그런 분기가 새로 필요하면 코드를
하나 더 만든다 — 문구 비교를 되살리지 않는다
([2026-09-17-i18n.md](log/2026-09-17-i18n.md) 의 "이유 코드").

**Rust 가 만드는 사용자 문구는 `tr!(ko:, en:)` 하나를 거친다** (`src-tauri/src/i18n.rs`) —
프런트로 올라가는 `Err(String)`·안내문·표시 이름이 그 대상이고, 주석·`eprintln!`·테스트 단언은
한국어 그대로다. **MCP 도구 설명·`initialize` instructions·AI 가 읽는 결과문은 영어 리터럴**
이다(사전도 `tr!` 도 아니다 — 읽는 것이 사람이 아니라 모델이라 표시 언어를 타면 안 된다).
`use crate::i18n::tr;` · 두 리터럴 모두 `format!` 을 지나므로 자리표시자가 어긋나면 컴파일이
멈춘다 (docs/log/2026-09-17-i18n.md 의 "Rust 쪽").

## 볼트 값은 프런트로 돌려주지 않는다 — `has_*`·`list` 만

`src-tauri/src/vault.rs` 의 `#[tauri::command]` 중 **비밀을 돌려주는 것은 하나도 없다.**
프런트가 받는 것은 상태 셋(`vault_status`), 종류와 대상(`vault_list`), `bool`(`vault_has_*`)
뿐이고, 값을 실제로 쓰는 `password_for`/`passphrase_for` 는 `pub(crate)` 라 IPC 표면에 없다
(docs/log/2026-09-19-vault.md ①의 5절).

화면이 늘어날 때 이 선이 무너진다 — "호스트 폼에 지금 담긴 비밀번호를 보여 줄까" 는 자연스러운
요구이고, 명령 하나만 내면 되기 때문이다. **내지 않는다.** 필요한 것은 언제나 "담겨 있는가"
까지이고(`has_*`), 목록이 필요하면 값 없는 `list` 다. 담는 방향(`vault_store_*`)만 열려 있다 —
그 값은 프런트가 방금 `open_ssh_session` 에 실어 보낸 바로 그 값이라 새로 여는 문이 아니다.

같은 이유로 **AI(MCP)에게는 어떤 문도 열려 있지 않다**: 볼트는 Tauri 명령 전용이다
(CLAUDE.md 의 "approve 는 Tauri 전용, MCP 아님" 과 같은 결).

## 크롬 글자를 얹는 상자는 크롬 면 — `--surface-tile` 은 터미널 색으로 그리는 것만

크롬 모드(다크/라이트)와 터미널 테마는 따로 고른다. `--surface-tile`(= `--term-bg-fill`)은 **터미널 테마**의
바탕이라, 그 위에 크롬 글자(`--fg-*`)를 얹으면 둘의 밝기가 갈리는 조합(라이트 크롬 + 어두운 터미널)에서 검은
바탕에 검은 글자가 된다. 입력 칸 · 드롭다운 · 정보 상자 · 카드 · 활성 탭 · 시작 화면 판 · 코드 블록은 `--surface-field`(우물)
또는 `--surface-raised` 같은 크롬 면을 쓴다(비치면 안 되는 자리는 `-solid` 짝). "타일과 이어 보이게" 도 이 규칙을 이기지 못한다. 한 번 옮겨 적은 "칸 = 타일 면" 이 40여 자리로 퍼진 뒤에야 보였다 — 글자색과 바탕이 **같은
쪽(크롬/터미널)**에서 오는지 칠할 때 본다 ([2026-10-01-field-surface.md](log/2026-10-01-field-surface.md)).

## 큰 면의 모서리는 토큰 둘 — 값을 박지 않는다

떠 있는 면(타일 · 런처 독 · 채팅 독 · 설정 모달 · 대화상자 · 메뉴 · 떠 있는 상태줄 · 시트 · 팝오버 · 가림막 카드)은
`--radius-surface`(16) 하나, 그 **안의 카드**는 한 단 작게 `--radius-surface-inner`(12)다. 단추 · 칩 · 탭은 알약(999px) 그대로, 작은
칸은 `--radius-sm`. 카드 안에 또 카드가 서면 계단으로 한 단씩 내린다(독 트리 펼침 판 12 · 10 — `calc(var(--radius-surface-inner) - 2px)` 꼴).
안쪽 칸을 바깥 곡선에 맞물리게 할 때는 **바깥 − 안쪽 여백 − 테두리**다(안쪽 칸이 카드일 때).
**한 줄짜리 목록 줄의 칠(호버 · 고른 줄)은 알약** `--radius-row`(2026-10-29 사용자 C안 — 명령 팔레트 · 메뉴 한 벌 `.menu-row` ·
독 목록 줄)이고 좌우 여백은 `--space-3` 이상(머리글도 같은 x). 두 줄 카드 · 40px 넘는 줄은 알약을 쓰지 않는다.
새 화면은 숫자를 박지 말고 이 토큰을 쓴다.
예외 하나: 창 아래 가운데 **즐겨찾기 독**은 한 줄짜리라 판이 완전한 알약(999px)이고 칸은 원이다(2026-10-26 사용자 — `StatusBar.svelte`
`.floating-menu` 머리말).

두 번째로 깨진 규칙이다: 2026-09-25 작업면 단계에서 모서리를 두 단(sm 7 · md 10)으로 접었는데(옛 `--radius-lg` 14 를 걷음), 그 뒤
화면마다 28 · 24 · 22 · 20 · 18 · 16 을 따로 박아 큰 면이 10 · 16 · 28 로 섞였다. 2026-10-25 사용자가 통일을 요청해 채팅 독 값 16 을
골랐다(`theme.css` 의 모서리 절 · 커밋 1d388b58 · 51ceff68 · 그 뒤 한 번 더 쓸었다).

## 토글 · 체크박스 · 라디오 — "남는 상태냐, 이번 한 번이냐"

- **토글**(`Toggle.svelte`) — 대상(연결 · 호스트 · 앨범 · 설정)에 **저장되어 계속 남는 켬/끔**. 설정 화면처럼 즉시 적용이든, 호스트 폼 ·
  DB 연결 폼처럼 [저장] 을 눌러야 적용이든 같다(비밀번호 저장 · 헤드리스 · 세션 로깅 · 계획 도구 …).
- **체크박스** — **이번 한 번의 동작에 딸린 선택**(워크트리를 지우면서 브랜치도 · 탭도 · 정리할 때 브랜치도), 목록에서 **여럿 고르기**,
  "이해했습니다" **확인**, 문서 **할 일**(`- [ ]`).
- **라디오** — 여럿 중 **하나만**.
- 체크박스 · 라디오는 OS 위젯을 쓰지 않는다 — `theme.css` 의 "앱 체크박스" 절이 토글과 같은 면 · 강조색으로 그린다(화면은 `<input>` 만 둔다).

업계의 흔한 권고("즉시 적용 = 스위치, 제출해야 적용 = 체크박스")를 그대로 따르지 않는 까닭: 이 앱은 Material 3 를 따르고 폼 안의 스위치가 이미
40개 넘게 자리 잡았다. 깨진 기록: 확인 · 저장 모달의 켬/끔이 체크박스로 섞였고(2026-11-13 전), 그날 일괄 토글로 바꾸다 워크트리 지우기의
"브랜치도 삭제" 같은 일회성 선택까지 토글이 되어 어색했다(사용자 실기 — 다시 체크박스로).

저장 키와 파일 이름(`workspaces.json` · `TabSpec` · `new-tab` · `open-sftp`)은 그대로 둔다 —
`settings.toml` 오버라이드를 이미 저장한 사용자가 잃는 것이 없어야 한다. 바꾸는 것은
화면에 보이는 문구뿐이다. (같은 이유로 `open-sftp` 는 라벨만 옮기고 id 를 지켰다. 예외는 사용자가 오버라이드 없음을 확인하고 승인한 한 번 —
2026-10-21 독 칸 id 를 `open-*-dock` 으로 통일했다(`open-hosts` → `open-hosts-dock` · `open-projects` → `open-projects-dock`).)

**저장 레이아웃은 워크스페이스로 이관하고 기능을 제거했다 (2026-10-02).** 화면의 타일 배열·새 타일 규칙·월페이퍼 맞춤의 "배치"는 그대로 쓴다. `layout.ts` 기하와 분할 트리도 유지한다.

**폐기 단축키 ID는 재사용하지 않는다.** `open-layouts`·`save-layout`은 `settings-codec.ts::DEPRECATED_ACTION_IDS`로 override를 보존하고 실행·설정·팔레트·도움말에서 제외한다. 폐기 override와 겹친 기본키는 자동 적용하지 않고 부팅 안내를 띄운다. Ctrl+Shift+S/K는 브라우저 가속키를 계속 막는다. 역사적 `workspace-1`…`9`는 탭 번호 선택이다.

**'함대/fleet' 은 쓰지 않는다 (2026-09-21 개명).** `~/.aynx/fleet.toml` 에 적히는 것은 배(船)의
떼가 아니라 **사용자가 호스트마다 AI 에게 준 권한 넷**이고, 앱은 승인된 작업이 그 호스트를
가리킬 때 그 허락에 기대어 타일 없이 붙는다. 그래서 파일·타입·명령·id 접두사(`delegated:`)·
i18n 키를 전부 **위임/delegation** 으로 옮겼다. **여기서 "헤드리스" 는 살아남는다** — 세션이
열린 **모양**을 가리키는 다른 축의 말이다. 위 표의 "id·식별자는 안 바뀐다" 규칙을 **한 번
어겼다**: 이 이름들은 사용자가 `settings.toml` 에 저장할 수 있는 키가 아니고, 남는 사용자
파일 하나(`fleet.toml`)는 첫 읽기에서 자동으로 새 이름으로 옮겨진다
([2026-09-21-rename-fleet-to-delegation.md](log/2026-09-21-rename-fleet-to-delegation.md)).

**'PuTTY식' 문구를 쓰지 않는다** — 터미널 우클릭 설정 라벨은 '메뉴 / 복사·붙여넣기'.
