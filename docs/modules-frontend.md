# 프런트 모듈 지도 (`src/lib/`)

[modules.md](modules.md)(백엔드)의 짝이다 — grep 없이 **고칠 파일을 찾는** 한 장. 불변식과 "왜" 는 각 파일
머리말에 있고 여기는 옮겨 적지 않는다. 지금은 `session` · `settings/model` · `dialogs` · `console` · `pane` · `term` · `shell-integration` · `browser`(파일 타일 몫) · `app/hosts` 아홉 묶음이 있다(2026-09-30 시작 — 다음 단계에서 늘린다).
폴더로 나누지 않은 주요 모듈은 아래 [폴더 밖 주요 모듈](#폴더-밖-주요-모듈) 표.

## 배럴 규칙

큰 모듈 하나를 폴더로 나눌 때는 **옛 파일을 배럴로 남긴다** (`src/lib/session.ts` → `src/lib/session/*.ts`).

- 배럴은 `export * from "./x/…"` **재수출만** 둔다 — 코드를 쓰지 않는다. 바깥(`$lib/session` · `./session` ·
  하니스의 경로 `lib/session.ts`)은 배럴을 부르고, 나누기 전과 같은 이름을 그대로 본다.
- 자식은 배럴(`../session` · `$lib/session`)을 **절대 부르지 않고** 형제를 직접 부른다.
- 모듈 수준의 바뀌는 상태(카운터·드래그 중 id)는 **자식 하나에만** 산다.
- 배럴이 내보내지 않는 **내부 전용** 자식이 있을 수 있다(머리말에 "내부 전용" 이라 적는다).
- `npm run check:cycles` 는 재수출(`export … from`)도 간선으로 센다 — 배럴을 거친 순환도 걸린다.

## `settings/model/` — 설정 모양·값·정규화·전역 상태·손잡이

배럴은 `src/lib/settings.svelte.ts`(바깥은 `$lib/settings.svelte.js` · 하니스는 경로 `lib/settings.svelte.ts`).
`src/lib/settings/*.svelte` 는 **설정 화면 섹션**(UI)이고 모델은 `model/` 에만 둔다. 룬은 `store.svelte.ts` 하나뿐이다 —
setter 는 `settings.current` 를 바꾸기만 해서 평범한 `.ts` 다.
설정 MCP 메뉴의 외부 서버 목록(요약)은 `settings/ExternalMcpServers.svelte`, 추가·편집은 하위 화면 `settings/McpServerEditor.svelte`
(순수 부분 `settings/model/mcp-server-form.ts`, 틀은 트리거·스니펫과 공용 `SubViewStack` · `SettingsSubView`)이고
`McpManager.svelte` 에서 부른다. 앱 전체·등록 로컬 프로젝트별 범위를 고르고 Rust `agent_mcp_validate` 로 검증한다.
맨 위 세션 서버 고정 줄도 켬/끔·Claude/Codex 대상 초안을 저장하며 다음 로컬 AI 타일 실행부터 실린다. 그 줄을 누르면 하위 화면
`settings/McpSessionsView.svelte`(상태 · 연결 대상 · 제공 도구 `mcp_tools` · 최근 호출 `mcp_calls`)가 열린다.
전역 등록·해제 토글과 설정 복사는 없고 펼친 정보에는 구동 상태·URL만 나온다.
stdio 환경변수 값은 `vault_store_mcp_env` 로만 보내고, 모델에는 이름·볼트 참조만 남긴다. 저장된 값은 되돌려 받지 않는다.

  xterm 은 같은 OSC 번호를 **나중에 건 것부터** 부르므로 셸 통합 뒤에 거는 `term/osc-handlers.ts`(52 · 9/777 · 7717)와의 순서는 `Terminal.svelte` `mount()` 몫이다.
- 배럴은 공개 조각 여섯만 내보낸다(`types` · `registry` · `cwd` · `marker` · `attach` · `badge`). 나머지는 **내부 전용**(머리말에 적혀 있다).

## `browser/` — 파일 타일(`SftpBrowser.svelte`)의 조각

`browser/` 는 파일 타일과 세션 타일(`Sidebar.svelte`)이 나눠 쓰는 그림·기계장치가 원래 살던 폴더다
(docs/log/2026-09-05-refactor-browsers.md). 2026-09-30 `src/lib/SftpBrowser.svelte`(1,731줄 · 스크립트 1,364줄)의 목록 읽기 ·
메뉴와 인라인 폼 · 항목 조작 · 키보드를 `file-*` 넷으로 더 떼었다(몸통 불변 — 바뀐 것은 참조·`this`·게터뿐). 배럴은 없다 —
경로로 부른다. 새 폴더(`sftp/`)를 만들지 않은 까닭: `$lib/sftp` 는 이미 `sftp.ts`(원격 편집 왕복) 자리라 배럴처럼 읽힌다.

- **`SftpBrowser.svelte` 에 남는 것:** 프롭 · 파생 값(`allRows` → 필터 → `rows` · `order` · `selPaths` · `targetDir` · 상태 줄 요약 …) · 장소 패널·남은 공간 읽기 · 파일 타일 층 단축키 실행(`runFileAction`) · 전송·드래그·마퀴·이력 배선 ·
  **모든 `$effect`**(선택 정리 · 느린 읽기 시계 · 게으른 읽기의 그물 · 끌며 머물면 펼치기 · 백엔드 따라가기(재연결) · 새로고침 번호 ·
  형제 타일 신호 · 로컬 자동 새로고침(감시 수명 · 볼 경로 · 미룸 풀림) · 글자 시계) · 마크업. 효과의 순서·수명이 나누기 전과 같다.
- **컨트롤러는 옛 상태 자리에서 하나 만든다**(`ls` · `mc` · `actions` · `keys`) — 수명 = 타일 수명. 타일의 값은 **게터 객체 하나**
  (`tile`)로 함께 받고, 조각마다 자기 몫의 모양(`File*Host`)으로만 읽는다(값으로 넘기면 한 프레임 낡는다).
- 메뉴 항목은 여전히 `FileMenu.svelte` 의 `onEntry` · `runAfterClose` 통로(`menu-runner.ts`)를 지난다 — 컨트롤러는 그 뒤에서 불리는 손잡이다.

## `app/hosts/` — 호스트 층(목록 · 여는 길 · 폼 · 우클릭 조작 · 공개키 설치)

배럴은 `src/lib/app/hosts.svelte.ts`(바깥은 `$lib/app/hosts.svelte.js` · 하니스는 경로 `app/hosts.svelte.ts` — 층의 머리말도 거기 있다).
2026-09-30 한 파일(1,777줄)에서 나눴다(몸통 불변 — 바뀐 것은 참조뿐: 형제로 옮긴 함수가 읽는 `cache` → `hostCache()`,
`mode`·`editOriginal` → `hostFormMode()`·`editOriginalName()`).

- **바뀌는 상태는 제 자식 하나에만 산다.** 다시 대입되는 룬(`let … = $state`)은 대입하는 함수와 한 파일이어야 해서,
  폼 세션 상태(`mode` · `editOriginal` · 오류 · 원본 메타 · 위임 원본 · `metaSeq` · `forwardRowError` …)와 그것을 쓰는 열기·닫기·저장은
  `form.svelte.ts` 에 함께 있다(그래서 이 파일만 540줄). 목록 캐시는 `list.svelte.ts`, 폼 객체는 `form-model.svelte.ts`,
  볼트 줄은 `saved-creds.svelte.ts`, 로그 폴더는 `session-logs.svelte.ts`, 빠른 접속 권유 표시는 `quick-connect.ts`.
- **볼트 불변:** 프런트가 보는 것은 `vault.hasPassword` · `vault.list` 의 **종류와 대상**뿐이고(값은 Rust 밖으로 나오지 않는다),
  폼에서 할 수 있는 일은 지우기(`vault.remove`)뿐이다. 담는 길은 접속 모달의 "이 앱에 저장" 하나(SSH·DB 공통 — `app/prompts`).
- 자식 사이 화살표에 순환이 없게 **지우기를 따로 뗐다**: `form` → `saved-creds`(열 때 채움) / `saved-creds-clear` → `form`(게터).

## `mirror/` — 원격 창의 집 PC 화면 거울(원격 웹 R2-B · 순수)

집 PC 주 창이 제 함수로 적용한 결과가 거울로 돌아온다. 요청으로 옮길 수 없는 둘(창 넘기기의 떼기 · 끼우기)만 `layoutLocked` 가 막는다.
